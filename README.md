
# **СУПЕРПРОМТ: ПРОЕКТ LUMEN ALPHA (CRM ДЛЯ ОЛЕГА) — ПОЛНЫЙ КОНТЕКСТ**

**Версия 14.2 (актуальная на 05.03.2026)**

**Статус:** Система полностью функциональна, развёрнута на сервере, прошла все ключестранные тесты. Исправлены критические ошибки, настроены бэкапы, улучшен UX. Проект готов к опытной эксплуатации и коммерческому использованию (on-premise). Ведутся работы по подготовке к масштабированию.

---

### **1. БИЗНЕС-КОНТЕКСТ**

**Пользователь:** Олег — менеджер/владелец малого бизнеса в сфере HVAC (установка и обслуживание кондиционеров).

**Цель:** Веб-приложение (Mobile First) для контроля заказов, финансов, напоминаний и прогнозирования спроса.

**Ключевые требования:**

- В каждом заказе может быть несколько единиц оборудования и различные услуги.
- Несколько монтажников с разными ролями и оплатой.
- Точный учёт финансов по каждой позиции, непредвиденные расходы.
- Гарантийные случаи с распределением ответственности.
- Прогнозирование спроса на основе истории заказов и погоды.
- **Коммерческий потенциал:** система может быть адаптирована для других сфер услуг (клининг, ремонт, доставка) и продаваться как коробочное решение.

**ИИ-ассистент:** старший инженер-наставник. Объясняет концепции, диктует код построчно, проверяет, закрепляет вопросами.

### **3. ТЕХНОЛОГИЧЕСКИЙ СТЕК (подтверждён актуальным аудитом)**

- **Backend:** Python 3.12 + FastAPI 0.104.1 (асинхронный)
- **Database:** PostgreSQL 15 (в Docker), asyncpg 0.29.0, SQLAlchemy 2.0.23
- **ORM:** SQLAlchemy 2.0 (asyncpg)
- **Планировщик:** APScheduler 3.10.4 + pgAgent (скрипт pgagent.sql)
- **Email:** fastapi-mail 1.4.1 (SMTP)
- **Геокодинг:** Яндекс.Карты (API‑ключ в .env, на фронте компонент AddressSuggest)
- **Погода:** Open-Meteo (сервис weather_service.py)
- **ML-сервис:** TensorFlow/Keras (tensorflow-cpu) + scikit-learn, joblib, pandas — отдельный контейнер (Dockerfile.ml)
- **Бэкапы:** Яндекс.Диск (библиотека yadisk 3.4.0), httpx, xlsxwriter — ежедневные дампы + Excel-отчёт с русскими заголовками и форматированием. В `docker-compose` добавлен volume для сохранения файлов локально.
- **Фронтенд:** React 19 (Create React App), React Router v7, recharts 3.7.0, react-select 5.10.2, @pbe/react-yandex-maps 1.2.5
- **Стили:** CSS-модули / обычные CSS + CSS-переменные для тёмной темы (ThemeContext)
- **Инфраструктура:** Docker Compose (БД, бэкенд, ML), nginx (reverse proxy), SSL (Let's Encrypt), защита от случайного `docker compose down -v` (скрипт install-protection.sh)

---

### **4. АРХИТЕКТУРНЫЕ РЕШЕНИЯ (НЕ НАРУШАТЬ!)**

- Бэкенд — только JSON API.
- Разработка локально (вне Docker). Docker только для БД и продакшена.
- Переменные окружения через `.env` + pydantic-settings.
- Асинхронный SQLAlchemy + asyncpg.
- Идемпотентный `init.sql` (полная схема с проверками существования объектов).
- Мягкое удаление (`deleted_at`) в таблицах `clients`, `installers`.
- Абсолютные импорты (в Python путь `src.*`).
- Mobile‑first на фронтенде.
- Тёмная тема через CSS-переменные и React Context (сохранение в localStorage).
- Защита данных: запрет на `docker compose down -v` через `install-protection.sh`, ежедневные бэкапы на Яндекс.Диск.
- **Реализовано:** мульти-позиционные заказы, учёт непредвиденных расходов, гарантийных случаев, расширенная таблица `finance`.

- Ежедневные бэкапы на Яндекс.Диск с ротацией по датам (локально и удалённо). Проверены вручную на сервере.
- В `docker-compose.yml` добавлен volume `./backups:/app/backups`, чтобы файлы сохранялись на хосте.
- Установлен `postgresql-client` в образ бэкенда для работы `pg_dump`.
- Параметры подключения к БД теперь берутся из `DATABASE_URL` (поддержка имён контейнеров и локального доступа).

#### ✅ ФРОНТЕНД

- **`NewOrder.jsx`:** поддержка нескольких позиций, нескольких монтажников, раздельные адреса клиента и заказа. Добавлены алерты при успехе/ошибке. Поле адреса заказа теперь необязательно (убрана звёздочка и `required`). Поля позиций и монтажников тоже необязательны.
- **`OrderDetail.jsx`:** отображение всех связанных сущностей, карта с меткой заказа, возможность добавлять расходы, платежи, гарантийные случаи. Поля даты заменены на `datetime-local`. Добавлена кнопка сброса для даты доставки. Во всех числовых полях реализовано выделение текста при фокусе. В поле адреса теперь используется `AddressSuggest` с автоподсказками (исправлен обработчик).
- **`OrdersList.jsx`:** колонки «Клиент», «Адрес», «Сумма» (выручка), «Статус». Работают фильтры. Исправлено отображение суммы (данные из `finance` подгружаются).
- **`InstallersList.jsx`:** добавлено сообщение при отсутствии мастеров, улучшена вёрстка таблицы.
- **`InstallerDetail.jsx`:** теперь корректно отображаются заказы, в которых участвует монтажник (через связь `order_installers`).
- **`MapPage.jsx`:** карта на весь экран, по клику на метку открывается заказ. Добавлена легенда цветов. Заказы со статусами «Выполнен» и «Отменен» скрыты с карты.
- **`Finance.jsx`:** сводка и график прибыли, ширина увеличена до 1400px. Добавлен чекбокс «Только выполненные», который фильтрует данные через параметр `completed`.
- **`AddInstaller.jsx`:** добавлен алерт при успешном создании мастера.
- **`api.js`:** динамический `BASE_URL` в зависимости от окружения (прокси для разработки, `/api` для продакшена). Методы финансов принимают параметры.

#### ✅ ИНФРАСТРУКТУРА И ДЕПЛОЙ

- Проект развёрнут на сервере (Ubuntu) с использованием Docker.
- Настроен nginx как reverse proxy: раздаёт статику фронтенда (папка `build`) и проксирует запросы на `/api`.
- Настроен HTTPS через Let's Encrypt.
- Установлена защита от случайного `docker compose down -v` через обёртку `~/bin/docker-compose`.
- **Настроен автозапуск:** Docker и nginx добавлены в автозагрузку, контейнеры имеют политику `restart: unless-stopped`.
- Унифицирован порт базы данных: локально используется `5433` (чтобы избежать конфликтов с локальным PostgreSQL), на сервере внутри контейнеров используется стандартный `5432`.

### **11. ПЕРСПЕКТИВЫ И МОНЕТИЗАЦИЯ**

Проект имеет высокий коммерческий потенциал:

- **Рынок:** малый бизнес в сфере услуг (клининг, ремонт, доставка, строительство) остро нуждается в недорогих, но функциональных CRM.
- **Конкуренты:** дорогие (AmoCRM, Bitrix24) либо слишком простые (Excel, Google Sheets). Наше решение — золотая середина.
- **Модель монетизации (ближайшая):**
  - **On-premise + кастомизация** — установка на сервер заказчика, доработки под его нужды.
  - **Разовая продажа лицензии** — от 50 000 ₽ за установку (включая базовую настройку).
  - **Ежегодное продление поддержки** — от 10 000 ₽/год (обновления, консультации).
- **Долгосрочная перспектива:** после накопления клиентской базы и стабилизации инфраструктуры можно переходить к SaaS-модели с ежемесячной подпиской (от 1 500 ₽/мес.).

**Следующий шаг:** упаковка продукта и выход на рынок через профильные форумы, Telegram-каналы и статьи на VC/Habr.

### **13. ТЕХНИЧЕСКИЙ ДОЛГ (ЧТО НУЖНО ДОРАБОТАТЬ ТЕХНИЧЕСКИ)**

- **ML-модуль:** модель не обучена, не интегрирована, требует подготовки данных и обучения.
- **Автотесты:** отсутствуют как на бэкенде, так и на фронтенде.
- **CI/CD:** нет автоматической сборки, тестирования и деплоя.
- **Мониторинг:** только базовые логи, нет системы оповещения при сбоях.
- **Документация API:** не сгенерирована (нет Swagger/ReDoc описаний, кроме автоматических).

Это не ошибки, а задачи на будущее. Проект работает и без них, но для коммерческого использования некоторые из них желательно закрыть.
